Sean's Font Prototyping Friend — INSTALL
=======================================

The app is a folder. You copy the folder, you run one command, and it opens in
your browser. There is no installer and nothing to register.

It needs Node.js. No Python, no admin rights, and no internet after the first
setup.


-----------------------------------------------------------------------------
WHAT IT NEEDS
-----------------------------------------------------------------------------

Node.js 22.18 or newer, 64-bit. Node 24 LTS is the one to get.

  https://nodejs.org  ->  the LTS download  ->  next, next, finish

To check what you have, open a Command Prompt and type:

      node --version

Anything from v22.18 upward is fine. Older than that will not run this: the
code is TypeScript, and Node runs TypeScript directly from that version on —
which is exactly why there is no build step and nothing to compile.


-----------------------------------------------------------------------------
FIRST RUN
-----------------------------------------------------------------------------

1. Copy the nameplate-app folder somewhere you keep programs, for example

       C:\Users\Zack\Documents\SeansFontPrototypingFriend\

   Anywhere you can write to is fine. Not C:\Program Files — that folder is
   read-only for normal users, so the app could not save settings.json or
   accept new fonts.

2. Open a Command Prompt in that folder (Shift+right-click the folder ->
   "Open PowerShell window here"), then:

       cd ts
       npm install        <-- once, needs internet; a minute or two
       npm start

3. It prints the address it is listening on:

       Sean's Font Prototyping Friend
         open http://127.0.0.1:8175/

   Open that in your browser. Chrome, Edge and Firefox all work.

4. Leave the Command Prompt window open while you use it — that window IS the
   app. Closing it stops the app. Ctrl+C stops it too.

To make it one double-click, put this in a .bat file next to the folder:

       @echo off
       cd /d "%~dp0ts"
       start "" http://127.0.0.1:8175/
       npm start

`npm install` is only needed once, or after the code changes.


-----------------------------------------------------------------------------
ON ANY OTHER COMPUTER
-----------------------------------------------------------------------------

Copy the whole folder over — USB stick, network share, OneDrive, whatever is
easiest — install Node.js on that machine, and run the same two commands.

If the other machine has no internet, copy the ts\node_modules folder across as
well and skip `npm install`.


-----------------------------------------------------------------------------
IT ONLY LISTENS TO THIS COMPUTER
-----------------------------------------------------------------------------

The address is 127.0.0.1, which means this machine and nothing else. Another PC
on the network cannot reach it, and there is no setting to change that. The app
reads and writes files on your disk by full path, which is right for a program
on your own machine and wrong for anything the network can talk to.


-----------------------------------------------------------------------------
ADDING YOUR FONTS
-----------------------------------------------------------------------------

The app ships with the three production fonts already in place. To add more:

  Either  click "Add font…" in the app (it copies the file into fonts\ for you)
  Or      drop the .ttf/.otf/.ttc into the fonts\ folder and click "Refresh"

Refresh also picks up a replaced font while the app is open — no restart. Use
"Reload font" after replacing a font with a new version under the same file
name; that re-reads the file from disk rather than the copy already in memory.

Because fonts live inside the app folder, they travel with it. Copy the folder
to another PC and your fonts go too.


-----------------------------------------------------------------------------
MAKING SURE THE SIZE IS EXACT IN CORELDRAW
-----------------------------------------------------------------------------

The exported files carry real physical size, and the geometry has been measured
to confirm it rather than assumed:

  PDF   accurate to 0.0003 pt  (0.000005 in)  <-- use this when size matters
  SVG   accurate to 0.00005 in (12 parts per million)

Both are far finer than any laser kerf. Nothing is scaled, stretched or
rounded to a different aspect ratio: changing the height scales the width by
exactly the same factor.

TO VERIFY IT YOURSELF, ONCE, ON A NEW PC:

1. In the app, type ADAM, set Height 1.000 in, Measured from = cap height.
   The app reports:  ADAM — 4.069 x 1.020 in
2. Export as PDF.
3. In CorelDRAW: File > Import, place it, then Edit > Select All.
4. Read the Object Size boxes in the property bar. They must read
   4.069 x 1.020 in.
5. Check the letters too, but know what to expect. "Cap height 1.000 in" means
   the CAP LINE is at exactly 1.000 in, and it lands there for every name you
   ever type. Individual letters read slightly over that on purpose, because
   type designers overshoot: this font's A measures 1.004 in (its pointed apex
   passes the cap line), a round O about 1.029 in. A flat-topped capital — H, E,
   I, T — is the one that measures exactly 1.000 in. The 1.020 total height
   includes the eyelet sitting above the letters.

   That is also why a name starting with J or Q is no longer smaller than one
   starting with A: the scale comes from the font's cap line, not from whichever
   capital happens to be first. A descender just hangs lower and makes the piece
   taller; it never shrinks the letters.

USE PDF IF YOU CAN for size. CorelDRAW's PDF import always honours physical
units. The SVG is equally exact and additionally keeps the CUT and ENGRAVE group
names and the 0.001 in hairlines, which the PDF does not — but some Corel
versions offer a resolution/DPI box on SVG import, and PDF avoids that question.

Set Corel's ruler units to inches (or mm) to match what you typed in the app,
or the numbers will look wrong when they are actually right.

WHAT IS AND ISN'T IN THE FILE
  In the file:   the cut outline, the red engrave centerlines, and lead-in
                 lines if you turned them on. Nothing else.
  NOT in it:     the dashed size box and the dimension labels you see in the
                 preview. Those are on-screen guides only, so there is nothing
                 extra for the laser to mistake for a cut. This is checked
                 automatically on every build.

Cut and engrave arrive as separate groups, CUT (black) and ENGRAVE (red), so
you can assign them to different laser layers. Lines are hairline, no fill.


-----------------------------------------------------------------------------
IF IT WON'T START
-----------------------------------------------------------------------------

"node is not recognised"
  Node.js is not installed, or the Command Prompt was open before you installed
  it. Close the window, open a new one, and try again.

"Unsupported TypeScript syntax" or a syntax error in a .ts file
  The Node on this machine is older than 22.18. Check with `node --version` and
  install the current LTS.

"EADDRINUSE" / "address already in use"
  The app is already running in another window, or something else has port
  8175. Use that window, or start it on a different port:

      node src/server.ts --port 9000

"Cannot find module" after copying the folder to another PC
  ts\node_modules did not come across. Run `npm install` in the ts folder, or
  copy that folder over as well.

The page loads but the font list is empty
  The fonts\ folder is missing or empty. It sits next to the ts folder, in the
  app folder itself. Put at least one .ttf/.otf in it and click Refresh. The
  app's Health button prints where it is looking.

It starts but won't save settings, or "Add font…" fails
  The folder is read-only. Move the app somewhere under your user folder or
  onto a data drive. Health says whether the folder is writable.

Something else
  Click "Health" in the app. It prints which build this is, where it keeps its
  files, and whether this machine can run it — that text is what to put in a
  bug report. The Command Prompt window also shows the real error rather than
  failing silently.


-----------------------------------------------------------------------------
REBUILDING (only if the code changes)
-----------------------------------------------------------------------------

From the ts folder:

  npm test                     every suite; nothing ships until they pass
  node scripts/build_all.ts    tests -> bundles -> staged folder -> tar.gz
  node scripts/verify_release.ts
                               extracts that archive somewhere clean, starts
                               the app out of it and drives it over HTTP

`build_all.ts` refuses to package if any suite fails, and proves the freshly
built bundle produces the documented numbers before it writes the archive.
